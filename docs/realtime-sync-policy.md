# 실시간 수신 적용 정책 — 동시 편집 발산 버그와 해결 기록

> 2026-07-31 · 관련 커밋: `b42135f`(1차 수정), `c4c3a07`(op 별 정책 확정, "임시조치")
> 코드: `frontend/src/pages/Dashboard/index.jsx` `applyOpToBoard` · `features/dashboard/realtime/opSequencer.js` · `useProjectOps.js`

## 겪은 버그

**재현**: A·B가 같은 블록을 동시에 잡고, A가 10시 위치에 놓고 B가 11시 위치에 놓는다.

- 증상 1 — 나중에 놓은 B의 화면만 A의 옛 위치(10시)에 갇힌다. 서버·A는 11시(정상).
- 증상 2 — 먼저 놓은 A가 B의 변경을 아예 못 받는 경우가 있다.

## 원인

**대원칙 위반**: 모든 클라이언트가 수렴하려면 *화면 = seq 순서로 op를 전부 적용한 결과*여야 한다. 두 지점에서 이 불변식이 깨졌다.

1. **자기 op 일괄 스킵 × 드래그 중 유예 큐** (증상 1)
   드래그 중 도착한 원격 op는 유예 큐에 쌓였다가 드롭 후 flush되는데, 이 flush(남의 **옛** op)가 방금 만든 내 낙관 반영을 덮는다. 그걸 서버 최종값으로 되돌려줄 내 op의 에코는 "자기 op = 이미 반영됨"이라는 가정으로 스킵돼 버려진다. 그 가정은 사이에 남의 op가 끼는 순간 무너진다.

2. **재연결 유실은 "다음 op"가 와야만 드러남** (증상 2)
   연결이 잠깐 끊긴 사이의 op는 이후 op가 도착해 seq 갭이 생겨야 감지된다. 상대의 드롭이 마지막 op면 그 "다음"이 영영 없어서 못 따라잡는다.

## 정책 3종 (① 구현됨 · ②③ **미구현/계획**)

> ⚠️ **주의**: 아래 ①만 실제 구현·검증됐다. ②(재연결 따라잡기)·③(영구 갭 폴백)은 **목표 설계이며 코드에 없다** — 재연결 후 유실 op·롤백 seq 갭 처리는 현재 미배선이다(3차 리뷰 §2·§4 OPEN). 디버깅 시 이 안전망이 있다고 가정하지 말 것.

### ① 자기 op도 종류별로 에코 적용 (일괄 스킵 금지)

시퀀서는 커서 전진을 위해 자기 op까지 전부 넘기고(자기 op도 seq를 소비한다), 적용 여부는 op 종류별로 정한다:

> 아래 표는 **블록·예산 op 한정**이다. `PROJECT_DELETED`·`PROJECT_STATUS_CHANGED`·`MEMBER_JOINED`·`MEMBER_LEFT`·`BUDGET_HEADCOUNT_CHANGED` 등 멤버십/프로젝트 라이프사이클 op는 이 표의 정책과 무관하게 별도 처리(토스트·이탈·재시드)된다.

| op | own 처리 | 이유 |
|---|---|---|
| `BLOCK_MOVED` | **적용(에코)** | 마지막 쓰기 승리형 — 남의 op에 덮인 자리를 자기 에코가 제 위치로 재확정 |
| `BLOCK_FIELD_UPDATED` | **적용(에코)** | 서버가 스테일 필드를 payload에서 빼고 보내므로, seq 순서 덮어쓰기 = 서버 최종값. 화면 y좌표가 startMins라 이게 빠지면 위치를 재확정해도 시각이 남의 값으로 남는다 |
| `BLOCK_CREATED` | 스킵 | 낙관 생성은 임시 id → POST 응답에서 서버 id로 교체되는데, 에코가 끼어들면 같은 블록이 두 벌 생긴다 |
| `BLOCK_DELETED` | 스킵 | 이미 로컬 제거됨 + 재적용하면 자기 삭제에 "다른 멤버가 삭제했어요" 토스트가 뜬다 |
| `TARGET_BUDGET_CHANGED` | 스킵 | 디바운스 저장 중이라 과거 값 에코가 최신 입력 표시와 싸운다 |
| `PROJECT_UPDATED` | 스킵 | 자기 변경으로 보드 전체를 재시드할 이유가 없다 |

부칙: own `BLOCK_MOVED`인데 로컬에 그 블록이 없으면(옮긴 직후 지운 경우) reload하지 않고 무시한다.

### ② 재연결마다 즉시 따라잡기 (⚠️ 미구현 — 계획)

**목표**: `useProjectOps`의 `onConnected`(최초 연결·모든 재연결)에서 시퀀서 `syncNow()` → `GET /ops?afterSeq={cursor}`로 유실분을 바로 메꾼다.

**현재**: `syncNow()`는 `opSequencer.js`에 정의만 있고 **호출부 0건**, `useProjectOps`에 `onConnected` 옵션이 없다. 재연결 후 유실 op는 다음 `reload()`까지 메워지지 않는다.

### ③ 영구 갭 폴백 (⚠️ 미구현 — 계획)

**목표**: 갭 재시도 6회(~3초)에도 진전이 없으면 스냅샷 reload로 수렴(롤백된 트랜잭션의 영구 갭에서 무한 대기 방지). `seq 갭이 N회 재시도에도 안 메워짐` 경고.

**현재**: 갭 재시도는 **무한 500ms 반복**(재시도 상한·`reload()` 폴백·경고문 모두 없음).

## 검증됨

같은 블록 동시 드래그(양방향 순서 모두) → 양쪽 화면이 마지막 드롭으로 수렴. 단독 편집 회귀 없음(에코가 낙관 반영과 같은 값이라 시각 변화 없음).

## "임시조치"인 이유 / 남은 것

op별 own 스위치는 새 op 타입이 생길 때마다 정책을 다시 정해야 하는 임기응변 성격이 있다. 장기 선택지:

- 이 정책 표를 dashboard-api.md(§X-Client-Id)에 계약으로 승격 — 명세는 현재 "일괄 스킵"을 권하는데 그 방식은 동시 편집에서 틀렸음이 실측됐다
- 또는 낙관 반영을 버리고 서버 에코만으로 그리는 재설계(입력 지연이 생기는 트레이드오프)

새 op 타입 추가 시 **"own일 때 재적용해도 무해한가?"** 를 반드시 판단하고 위 표에 추가할 것.
