# 4. 시연 시나리오

**화면 → 클릭 위치 → 확인 포인트** 순으로 적었다.

이 서비스의 핵심은 **여러 명이 동시에 편집하는 것**이라, 시연은 반드시
**브라우저 두 개(다른 계정)** 를 나란히 놓고 진행한다.

| | |
|---|---|
| 접속 주소 | 로컬 `http://localhost:5173` / 배포 `https://<도메인>` |
| 소요 시간 | 약 5분 |
| 준비물 | 카카오 계정 2개, 브라우저 2개, 이어폰(하울링 방지) |

> ⚠️ 로컬 시연은 반드시 **`localhost`** 로 접속한다. `http://<내부IP>:5173` 으로
> 접속하면 보안 컨텍스트가 아니어서 **음성 채팅(4번)이 동작하지 않는다.**

---

## 0. 사전 준비 — 시연 전에 끝내 둘 것

실시간 데모는 준비 상태에서 시작해야 시간 안에 끝난다.

| # | 준비 | 이유 |
|---|---|---|
| 1 | **창 A**(주 계정) / **창 B**(다른 계정, 시크릿 창) 를 화면 좌우로 배치 | 한 화면에 둘 다 보여야 "동시"가 전달된다 |
| 2 | 양쪽 모두 **같은 프로젝트 대시보드까지 진입** | 로그인·진입 과정은 시연 대상이 아니다 |
| 3 | 양쪽 모두 **마이크 권한 허용** | 권한 팝업이 시연 중에 뜨면 흐름이 끊긴다 |
| 4 | 후보 목록에 블록 **3~4개** 미리 담아 두기 | 검색부터 하면 2분이 날아간다 |
| 5 | Day 1 에 블록 2~3개 배치 (오전~오후) | 빈 타임라인은 밋밋하다 |
| 6 | 이어폰 착용 | 두 브라우저 스피커가 서로를 물면 하울링 |

> 서로 다른 계정이 필요한 이유 — 접속 배지·커서·편집 배지는 `memberId` 기준이라
> **같은 계정의 두 탭은 서로를 "남"으로 보지 않는다.**

## 1. 랜딩 · 로그인 (선택, 30초)

시간이 빠듯하면 건너뛰고 0-2 상태에서 시작한다.

| 화면 | 조작 | 확인 |
|---|---|---|
| 랜딩 (`http://localhost:5173`) | 좌측 히어로 "여행을 잇는 길, 이음길" | 브랜드 인지 |
| | 우측 카드의 **[카카오로 시작하기]** 클릭 | 카카오 인증 페이지로 이동 |
| 카카오 동의 | 동의하고 계속하기 | `/oauth/kakao/callback` 경유 후 개인 페이지 진입 |

**멘트** — "인증은 카카오 로그인만 씁니다. 자체 회원가입은 없습니다."

## 2. 그룹 · 프로젝트 (선택, 40초)

| 화면 | 조작 | 확인 |
|---|---|---|
| 개인 페이지 (`/my`) | 좌측 **[내 그룹]** 목록 | 참여 중인 그룹 카드 |
| | 우상단 **[＋ 새 그룹]** | 그룹 생성 모달 |
| | 또는 **[초대 코드로 입장]** 에 코드 입력 (예: `YJ3K7Q2M`) | 그룹 합류 |
| 그룹 페이지 | 그룹 카드를 **클릭해 입장** | 프로젝트 목록 |
| | **[＋ 새 프로젝트]** | "새 여행 프로젝트" 모달 |
| 프로젝트 생성 모달 | 프로젝트 이름 / 목적지 / 시작일 / 종료일 / 인원 입력 | 기간이 곧 Day 탭 개수가 된다 |
| | **출발지점 (선택)** 에 장소 검색 | 입력하면 **Day 1 09:00 에 시작 블록**이 자동 생성되고 지도 초기 위치가 그곳이 된다 |
| | 생성 → 대시보드 진입 | |

**멘트** — "여행 기간을 넣으면 Day 탭이 그만큼 생깁니다. 출발지점을 넣으면 첫 블록이 미리 놓입니다."

## 3. ★ 실시간 협업 (90초) — 시연의 핵심

**여기가 전부다.** 창 A 에서 조작하고 **창 B 를 가리키며** 말한다.

| # | 조작 (창 A) | 창 B 에서 확인 |
|---|---|---|
| 1 | 후보 목록의 블록을 타임라인 **14:00 부근**으로 드래그 | **즉시 같은 위치에 나타난다** |
| 2 | 마우스를 타임라인 위에서 천천히 움직임 | **이름표가 달린 커서**가 따라 움직인다 |
| 3 | Day 2 탭 클릭 | Day 2 탭에 **A 의 프로필 아바타**가 붙는다 |
| 4 | (헤더 오른쪽) 접속 배지 | 접속 중인 멤버 아바타 (최대 4명 + 나머지 수) |
| 5 | 블록을 클릭해 편집 폼 열기 | 그 블록에 **"OOO 편집 중"** 배지 |
| 6 | 이름을 바꾸고 저장 | 블록 좌상단 **마지막 수정자 아바타**가 A 로 바뀐다 |

**멘트**
- 1번: "서버 응답을 기다리지 않고 화면이 먼저 움직입니다."
- 2번: "누가 어디를 보고 있는지도 보입니다. 스크롤 위치가 서로 달라도 **같은 시간 위치**에 그려집니다."
- 5번: "편집 중이라고 알려주지만 **잠그지는 않습니다.** 브라우저가 죽은 사람 때문에 블록이 묶이는 게 더 나쁘니까요."

## 4. 음성 채팅 (30초)

| 화면 | 조작 | 확인 |
|---|---|---|
| 화면 하단 가장자리 | 음성 탭(🎤/🔇)을 클릭해 펼침 | 마이크·스피커 버튼, 참여자 아바타, "음성 연결됨 · N명" |
| | 마이크 버튼(🔇 → 🎤) 클릭 | 음소거 해제 |
| | 말한다 | **말하는 사람 아바타에 링**이 켜진다 (양쪽 화면 모두) |
| | 탭을 다시 눌러 접음 | 접혀도 **탭 테두리가 링 역할** — 연결은 유지된다 |

**멘트** — "들어오면 자동으로 연결되고, 마이크는 **음소거 상태로** 시작합니다.
연결된 줄 모르고 말하는 사고를 막으려고요."

> ⚠️ 두 브라우저가 같은 기기면 이어폰을 쓴다. 스피커로 하면 하울링이 난다.
> ⚠️ 서로 다른 네트워크(기관망 등)에 있으면 연결이 안 될 수 있다(TURN 미구성).

## 5. 일정 편집 디테일 (60초)

| # | 조작 | 확인 |
|---|---|---|
| 1 | 블록 **아래 가장자리**를 잡고 아래로 드래그 | 소요 시간이 늘고 **아래 블록들이 실시간으로 밀린다** |
| 2 | 블록 사이 빈 곳의 **🚗 버튼** 클릭 | 교통 후보 모달 — 여러 경로 중 선택 |
| 3 | 경로 카드를 클릭해 선택 | 이동 블록 생성 + **소요 시간 자동 반영** |
| 4 | 계획표 헤더의 **[🚗 이동수단 자동 생성]** | Day 전 구간을 한 번에 계산 → 통합 모달 |
| 5 | 블록을 **23:00 부근**으로 드래그 (2시간짜리) | 토스트: **"24:00을 넘어 Day 2 에 …"** — 자정에서 잘려 다음 Day 로 이어진다 |
| 6 | 블록을 보드 **바깥**으로 끌고 감 | 화면에 빨간 테두리 + **"🗑 범위 밖에 놓으면 삭제됩니다"** |

**멘트**
- 5번: "밤을 넘기는 일정은 여행에서 정상입니다. 오류를 내는 대신 **잘라서 다음 날로 넘깁니다.**"
- 6번: "휴지통 영역을 따로 두지 않은 대신, 규칙이 보이게 했습니다."

## 6. AI 챗봇 · 지도 · 예산 (60초)

| 화면 | 조작 | 확인 |
|---|---|---|
| 우하단 챗봇 버튼 | 클릭해 "이음이" 열기 | 대화창 |
| | **지도 모드**로 전환 후 "근처 맛집 추천해줘" | "이음이가 생각 중" → **지금 보고 있는 지도 범위 안**에서 추천 |
| | 응답 확인 | 마크다운(표 포함)으로 렌더링, 링크는 새 탭 |
| | 추천 **카드를 드래그**해 후보 목록에 놓기 | 블록으로 담긴다 |
| 사이드 [카카오 장소 검색] | 키워드 검색 → 결과 클릭 | 지도가 그 위치로 이동, 핀 표시 |
| | 결과를 드래그해 후보 목록에 | 블록으로 담긴다 |
| 사이드 [예산] | 블록에 비용 입력 후 확인 | **블록별로 색이 다른 막대**, 1인당 금액, 희망 예산 대비 사용률 |

**멘트** — "추천은 '＋ 추가' 버튼이 아니라 **끌어다 놓습니다.** 이 화면의 조작 문법이
처음부터 끝까지 드래그라서요."

## 돌발 상황 대비

| 증상 | 즉시 확인 |
|---|---|
| 실시간 반영이 안 됨 | DevTools > Network > **WS 탭에 `/ws` 가 101** 인지. 아니면 nginx Upgrade 헤더 |
| 지도만 회색 | 카카오 콘솔 > 플랫폼 > Web > **사이트 도메인** 등록 |
| 마이크 권한 팝업이 안 뜸 | 주소창 자물쇠 > 사이트 설정 > 마이크 허용 |
| 음성이 연결 안 됨 | 두 기기가 **같은 네트워크**인지 (TURN 미구성) |
| 일정이 전부 후보 목록에 있음 | **마이그레이션 006 미실행** ([03 문서](./03-DB-덤프.md)) |
| 교통 추천이 502 | ODsay 일일 쿼터 소진 |
| 챗봇이 502 | GMS 크레딧 확인 |

## 시간이 부족할 때 자르는 순서

1. **1·2번(로그인·프로젝트 생성)** — 준비 상태에서 시작
2. **7번(읽기 모드)** — 한마디로 대체
3. **6번의 지도 검색** — 챗봇만 보여줌

**3번(실시간 협업)은 절대 자르지 않는다.** 이 서비스의 존재 이유 전체가 거기 있다.
