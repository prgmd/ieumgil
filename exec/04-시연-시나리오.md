# 4. 기능 시연 가이드

서비스의 **모든 기능**을 하나씩 확인하는 문서.
기능마다 *위치 → 조작 → 확인 포인트 → 설명* 순으로 적었다.

| | |
|---|---|
| 접속 주소 | 로컬 `http://localhost:5173` / 배포 `https://i15a107.p.ssafy.io` |
| 준비물 | **카카오 계정 2개**, 브라우저 2개, 이어폰 |
| 전체 소요 | 20~25분 (전 기능 확인 기준) |

시간이 없다면 [§14 압축 시연 코스](#14-압축-시연-코스-8분)를 따른다.

---

## 시작 전 — 계정 2개가 필요한 이유

접속 배지·라이브 커서·편집 중 배지·마지막 수정자는 전부 `memberId` 기준이라,
**같은 계정의 두 탭은 서로를 "남"으로 보지 않는다.** 계정 하나로는 §6 실시간 기능이
하나도 보이지 않는다.

| | 창 A | 창 B |
|---|---|---|
| 브라우저 | 일반 창 | **시크릿 창** (또는 다른 브라우저) |
| 계정 | 카카오 계정 ① | 카카오 계정 ② |

> 시크릿 창을 쓰는 이유 — 같은 브라우저의 일반 창은 카카오 세션을 공유해서 두 번째
> 로그인이 첫 계정으로 그냥 통과된다.

### ⚠️ 로컬은 반드시 `localhost` 로 접속

`http://<내부IP>:5173` 은 보안 컨텍스트가 아니어서 **음성 채팅(§7)과 초대 링크
복사가 동작하지 않는다.** 다른 기기에서 확인하려면 HTTPS 가 필요하다.

# 1. 인증

## 1-1. 카카오 로그인

| | |
|---|---|
| 위치 | 랜딩 (`/`) 우측 카드 |
| 조작 | **[카카오로 시작하기]** → 카카오 동의 → 자동 복귀 |
| 확인 | `/oauth/kakao/callback` 을 거쳐 개인 페이지(`/my`) 진입, 우상단에 프로필 |

자체 회원가입·비밀번호가 없다. 첫 로그인 시 카카오 **닉네임과 프로필 이미지**를
받아 회원이 생성된다.

## 1-2. 세션 유지

| | |
|---|---|
| 조작 | 로그인 후 **F5 새로고침** |
| 확인 | 로그인 상태가 유지된다 |

accessToken 은 30분, refreshToken 은 14일이며 **httpOnly 쿠키**로 저장된다.
만료되면 화면 조작 없이 자동 재발급된다.

## 1-3. 로그아웃

| | |
|---|---|
| 위치 | 개인 페이지 좌측 **[계정]** 섹션 |
| 확인 | 랜딩으로 돌아가고, 새로고침해도 로그인 상태가 아니다 |

## 1-4. 회원 탈퇴

| | |
|---|---|
| 위치 | 개인 페이지 **[계정]** > 탈퇴 |
| 조작 | 확인란에 **`탈퇴합니다`** 를 직접 입력해야 버튼이 활성화된다 |
| 확인 | "정말 탈퇴할까요?" 모달 — **혼자만 있는 그룹은 함께 삭제**된다고 경고 |

> 오타 하나로 계정이 사라지지 않도록 문구 입력을 요구한다. 남기고 싶은 그룹이
> 있으면 먼저 팀원을 초대하라고 안내한다.

# 2. 그룹

## 2-1. 그룹 목록

| | |
|---|---|
| 위치 | 개인 페이지 좌측 **[내 그룹]** |
| 확인 | 처음에는 비어 있다. 그룹 카드에 이름·멤버 수 |

## 2-2. 그룹 생성

| | |
|---|---|
| 조작 | 우상단 **[＋ 새 그룹]** → **그룹 이름** 입력(2~20자) → 생성 |
| 확인 | 생성 직후 **초대 코드 공유 모달**이 바로 뜬다 |

## 2-3. 초대 코드

| | |
|---|---|
| 위치 | 생성 직후 모달 / 그룹 페이지 상단 |
| 확인 | **8자리 대문자+숫자** (예: `YJ3K7Q2M`), 남은 유효기간 표시 |
| 조작 | **[복사]** → 토스트 "초대 코드가 복사됐어요 🔗" |
| 조작 | **[재발급]** → 토스트 "코드 재발급 — 기존 코드는 즉시 무효화됐어요" |

발급 후 **7일간 유효**하다. 만료되면 재발급하면 되고, 그룹 멤버 **누구나** 재발급할
수 있다.

> `navigator.clipboard` 는 보안 컨텍스트를 요구한다. IP 로 접속했다면 복사가 실패하고
> "코드를 직접 선택해 복사해주세요" 토스트가 뜬다.

## 2-4. 초대 코드로 입장 (창 B)

| | |
|---|---|
| 위치 | 개인 페이지 **[초대 코드로 입장]** |
| 조작 | 코드 8자리 입력 → 입장 |
| 확인 | 그룹 목록에 나타난다. 창 A 를 새로고침하면 **멤버 2명** |

## 2-5. 그룹명 수정

| | |
|---|---|
| 위치 | 그룹 페이지 그룹명 옆 ✎ (title="그룹명 수정") |

## 2-6. 그룹 나가기

| | |
|---|---|
| 위치 | 그룹 페이지 |
| 확인 | "그룹을 나갈까요?" — 나간 뒤에도 **유효한 초대 코드로 다시 입장**할 수 있다 |

# 3. 프로젝트

## 3-1. 프로젝트 생성

| | |
|---|---|
| 위치 | 그룹 페이지 우상단 **[＋ 새 프로젝트]** |
| 입력 | **프로젝트 이름 \*** / **목적지 \***(예: 부산) / **여행 시작일 \*** / **여행 종료일 \*** / **여행 인원 \*** |
| 입력 | **출발지점 (선택)** — 장소 검색 |

**확인 포인트 3가지**

- 여행 기간이 곧 **Day 탭 개수**가 된다 (2박 3일 → Day 1~3)
- 인원은 예산의 **1인당 계산 기준**이 된다
- 출발지점을 넣으면 **Day 1 09:00 에 시작 블록이 자동 생성**되고, 사이드 **지도의
  초기 위치**가 그 장소가 된다

> 빈 화면에서 시작하지 않게 하려는 장치다. 넣지 않으면 완전히 빈 보드로 시작한다.

## 3-2. 프로젝트 수정 / 삭제

| | |
|---|---|
| 위치 | 그룹 페이지 카드의 ✎ / 🗑 (title="프로젝트 수정" / "프로젝트 삭제") |
| 위치 | 대시보드 상단바 제목 옆 ✎ 로도 수정 가능 |
| 확인 | 기간을 바꾸면 **Day 탭 개수가 즉시 따라 바뀐다** |

기간을 줄여 사라진 Day 에 블록이 남아 있으면 **버리지 않고 후보 목록으로 되돌린다.**

## 3-3. 지난 여행 구분

| | |
|---|---|
| 확인 | 종료일이 지난 프로젝트는 카드가 구분되어 표시된다 |

# 4. 대시보드 — 기본 구조

## 4-1. 화면 구성

```
[상단바]  프로젝트 제목 ✎ | 편집/읽기 토글 | 접속 배지 | 프로필
[좌]  Day 탭      [중앙]  계획표(타임라인) + 후보 목록      [우]  예산 · 지도 · 장소 검색
                                                        [우하단] 챗봇  [하단] 음성 바
```

## 4-2. Day 탭

| | |
|---|---|
| 위치 | 화면 왼쪽, 책갈피 모양 |
| 확인 | Day 번호 / 날짜 / **그 Day 의 블록 수** |
| 확인 | 다른 멤버가 그 Day 를 보고 있으면 **프로필 아바타**가 붙는다 (§6-4) |

선택된 탭만 보드와 같은 크림색이라 펼쳐진 페이지처럼 이어진다.

## 4-3. 타임라인

| | |
|---|---|
| 위치 | 계획표 카드 안 |
| 확인 | **00:00 ~ 24:00 전체**를 덮는다. 1분당 2px 이라 **블록 길이 = 소요 시간** |
| 조작 | Day 를 열면 첫 블록(없으면 09:00) 위치로 자동 스크롤 |

## 4-4. 후보 목록 (POOL)

| | |
|---|---|
| 위치 | 계획표 아래 |
| 확인 | 아직 시간을 정하지 않은 블록의 보관함. 한 줄에 5개 |
| 확인 | 비어 있으면 **"아직 보관한 블록이 없어요 — …"** 안내가 중앙에 뜬다 |

검색 결과·챗봇 추천은 **반드시 여기를 거쳐** 타임라인에 오른다.

## 4-5. 후보 목록 필터 · 검색

| | |
|---|---|
| 위치 | 후보 목록 헤더 오른쪽 |
| 조작 | **대분류 선택** — 전체 / 명소·활동 / 식당 / 숙소 / 교통 / 기타 |
| 조작 | **제목 검색** 입력 |
| 확인 | 헤더 숫자가 `보이는 개수/전체 개수` 로 바뀐다 (예: `3/12`) |
| 조작 | 필터가 걸리면 나타나는 **초기화 버튼**(aria-label="필터 초기화") |

**거르는 것은 표시뿐**이다 — 필터를 걸어도 블록이 사라지거나 순서가 바뀌지 않는다.

## 4-6. 커스텀 블록

| | |
|---|---|
| 위치 | 후보 목록 헤더 **[+ 커스텀 블록]** |
| 확인 | 검색에 없는 일정(휴식, 이동 등)을 직접 만든다. 후보 목록에 생성된다 |

## 4-7. 블록 편집 폼

| | |
|---|---|
| 조작 | 블록 **카드를 클릭** (끌기도 그대로 된다) |
| 입력 | **장소명** / **대분류** / **소분류**(예: 회, 산책) / **소요 (분)** / 예산 / **블록 상세** |
| 입력 | 주소 — **주소 검색** 버튼으로 도로명 주소 선택 |
| 입력 | **이동 수단** (교통 블록) |

**협업에서 중요한 동작** — 저장할 때 **폼을 열었을 때의 값과 비교해 내가 실제로 손댄
필드만** 보낸다. 손대지 않은 필드는 그 사이 남이 바꾼 값이 그대로 살아남는다.

> 확인 방법 — 창 A 에서 폼을 열어 둔 채 창 B 에서 같은 블록의 예산을 바꾼다.
> 창 A 에서 이름만 고쳐 저장하면 **B 가 바꾼 예산이 유지된다.**

# 5. 일정 배치

## 5-1. 드래그로 배치

| 방향 | 조작 | 확인 |
|---|---|---|
| 후보 → 타임라인 | 원하는 시각으로 끌어다 놓기 | 그 시각에 블록이 놓인다 (1분 단위) |
| 타임라인 → 후보 | 아래로 끌어 내림 | 시각 없는 상태로 되돌아간다 |
| 후보 안 재정렬 | 카드끼리 위치 교환 | |
| Day 간 이동 | 후보로 내렸다가 다른 Day 로 | |

## 5-2. 리사이즈

| | |
|---|---|
| 조작 | 블록 **위·아래 가장자리**를 잡고 드래그 |
| 확인 | 소요 시간이 바뀌고, **아래 블록들이 실시간으로 밀린다** |

## 5-3. 겹침 자동 해소

| | |
|---|---|
| 조작 | 이미 블록이 있는 시간대에 다른 블록을 끼워 넣기 |
| 확인 | 뒤 블록들이 **필요한 만큼만** 밀린다 |
| 확인 | 사이에 **빈 시간이 있으면 거기서 밀림이 흡수**되어 그 뒤는 안 움직인다 |

무조건 다 미는 것이 아니라, 붙어 있는 구간에서만 전파된다.

## 5-4. 자정 넘김 자동 분할 ★

| | |
|---|---|
| 조작 | 2시간짜리 블록을 **23:00 부근**에 놓기 |
| 확인 | 토스트 **"24:00을 넘어 Day 2 에 1개를 이어서 만들었어요"** |
| 확인 | **Day 2 탭** 00:00 에 **"(이어서)" 블록**이 생성되어 있다 |
| 확인 | 원본은 24:00 까지로 줄어 있고, **비용은 원본에만** 남는다 |

밤을 넘기는 일정은 여행에서 정상이다. 오류를 내는 대신 잘라서 다음 날로 넘긴다.
다음 Day 도 넘치면 연쇄로 이어지고, **마지막 Day 에서 넘칠 때만 거부**한다.

## 5-5. 삭제

| | |
|---|---|
| 조작 | 블록을 **보드 바깥**으로 끌고 감 (놓기 전) |
| 확인 | 화면 가장자리에 빨간 테두리 + **"🗑 범위 밖에 놓으면 삭제됩니다"** |
| 확인 | 보드 안으로 되돌리면 경고가 사라진다 |

전용 휴지통 영역을 없앤 대신 후보 목록이 그만큼 넓어졌다. 배너는 반투명이라 뒤의
보드를 보면서 놓을 수 있다.

# 6. 실시간 협업 ★ — 이 서비스의 핵심

**창 A 에서 조작하고 창 B 를 보면서 확인한다.**

## 6-1. 동시 편집

| 조작 (창 A) | 확인 (창 B) |
|---|---|
| 블록 생성 / 이동 / 수정 / 삭제 | **즉시** 같은 결과가 나타난다 |
| 창 B 에서도 조작 | 창 A 에 반영 (양방향) |

새로고침 없이 반영된다. 서버가 확정한 순서대로 모두가 같은 결과에 도달한다.

## 6-2. 라이브 커서

| | |
|---|---|
| 조작 | 창 A 에서 마우스를 천천히 움직임 |
| 확인 | 창 B 에 **이름표 달린 커서**가 따라온다 |
| 확인 | 타임라인 밖(후보 목록·사이드)에서도 보인다 |

**스크롤을 다르게 해도 같은 시각을 가리킨다** — 타임라인 안에서는 좌표를 픽셀이
아니라 **시각(분)** 으로 보내기 때문이다. 창 A 에서 타임라인을 스크롤한 뒤 다시
움직여 확인한다.

5초간 갱신이 없으면 커서가 사라진다(이탈 신호가 유실돼도 잔상이 안 남게).

## 6-3. 접속 배지

| | |
|---|---|
| 위치 | 상단바 오른쪽 |
| 확인 | 지금 이 프로젝트를 보고 있는 멤버 아바타 |
| 확인 | **최대 4명까지** 표시하고 나머지는 숫자로 줄인다 |

## 6-4. Day 탭 "보는 중"

| | |
|---|---|
| 조작 | 창 A 에서 **Day 2 탭** 클릭 |
| 확인 | 창 B 의 Day 2 탭에 **A 의 프로필 아바타** |

**다른 Day 를 보는 사람의 커서는 그리지 않는다.** 서로 다른 화면 위에 커서만 겹치면
"저 사람이 내 화면을 가리킨다"는 착시가 생기기 때문이다. 위치는 숨기고 존재만 남긴다.

## 6-5. 편집 중 배지

| | |
|---|---|
| 조작 | 창 A 에서 블록을 클릭해 편집 폼 열기 |
| 확인 | 창 B 의 그 블록에 **"OOO 편집 중"** 배지 |
| 확인 | **창 B 에서도 같은 블록을 열 수 있다** — 잠그지 않는다 |

진짜로 잠그면 브라우저가 죽은 사람 때문에 블록이 30초씩 묶인다. 막기보다 알리는
쪽을 택했다.

## 6-6. 마지막 수정자

| | |
|---|---|
| 조작 | 창 A 에서 블록 이름을 바꾸고 저장 |
| 확인 | 양쪽 화면 블록 **좌상단에 A 의 프로필 아바타** |
| 확인 | **새로고침해도 남는다** (서버에 영속) |

## 6-7. 필드 단위 충돌 처리

| | |
|---|---|
| 조작 | 창 A 는 **이름**, 창 B 는 **예산**을 같은 블록에서 동시에 수정 |
| 확인 | **둘 다 살아남는다** |

블록 전체가 아니라 **필드마다** 마지막 쓰기 시각을 관리한다.

## 6-8. 멤버 색

| | |
|---|---|
| 확인 | 커서·Day 탭 아바타 테두리가 멤버마다 **고정된 색** |
| 확인 | 로그아웃 후 다시 들어와도 **같은 색** |

# 부록. 데이터 상태에 대해

DB 덤프를 별도로 제공하지 않는다. 인증이 **카카오 로그인 전용**이라 실행하는 사람의
계정은 항상 신규로 생성되고, 남이 만든 그룹·프로젝트에는 접근 경로가 없기 때문이다.
**덤프를 복원해도 화면에는 아무것도 보이지 않는다.**

스키마는 `DDL_AUTO=update` 로 기동할 때 JPA 가 엔티티 기준으로 자동 생성하므로
초기화 스크립트도 필요 없다. → [01 문서](./01-빌드-배포-매뉴얼.md)

대신 **빈 상태에서 시작하는 것 자체가 온보딩 확인**이 되도록 §1~§3 을 구성했다.
로그인부터 일정이 채워진 보드까지 3분이면 도달한다.
