### 03. DB 덤프를 제공하지 않는 이유

인증이 **카카오 로그인 전용**이라 실행하는 사람의 계정은 항상 신규로 생성되고,
남이 만든 그룹·프로젝트에는 접근 경로가 없다. **덤프를 복원해도 화면에는 아무것도
보이지 않는다.**

스키마 역시 `DDL_AUTO=update` 로 기동할 때 JPA 가 엔티티 기준으로 자동 생성하므로
초기화 스크립트가 필요 없다.

대신 **빈 상태에서 시작하는 것 자체가 온보딩 시연**이 되도록
[04 문서](./04-시연-시나리오.md)의 PART A~B 를 구성했다. 그룹 생성 → 초대 코드
합류 → 프로젝트 생성 → 일정 채우기까지 3분이면 충분하다.

## 실행 요약

```bash
git clone <저장소 URL> ieumgil && cd ieumgil

cd backend
vi .env                                  # 새로 작성 (01 문서 STEP 2 템플릿)
docker compose up -d --build backend     # backend + postgres + redis

cd ../frontend
vi .env                                  # 새로 작성 (01 문서 STEP 4 템플릿)
npm install
npm run dev
```

`.env` 두 개는 `.gitignore` 로 제외되어 저장소에 없다.
**[01 문서](./01-빌드-배포-매뉴얼.md)의 STEP 2·4 템플릿을 붙여넣어 새로 만든다.**

→ **`http://localhost:5173`**

## 구성

```
브라우저 ──> Vite dev server (5173)
               ├─ 정적 자원
               ├─ /api  ─┐
               └─ /ws   ─┤ 프록시 (ws: true)
                         ↓
               ┌─ Docker Compose ─────────────────────┐
               │  backend (8080) ── postgres (5432)   │
               │                 └─ redis (6379)      │
               └──────────────────────────────────────┘
```

프론트엔드는 컨테이너에 올리지 않는다. Vite dev server 가 `/api`·`/ws` 를 백엔드로
프록시하므로 브라우저 입장에서 **단일 오리진**이 되고, 이 구조가 배포(nginx 리버스
프록시)와 같은 모양이다.

## 제품·버전 요약

| 구분 | 제품 | 버전 |
|---|---|---|
| JVM | Eclipse Temurin JDK / JRE | **21** |
| 프레임워크 | Spring Boot | **3.4.13** |
| WAS | 내장 Tomcat (starter-web) | Boot 3.4.13 동봉 |
| 빌드 도구 | Gradle Wrapper | **8.12** |
| DB | PostgreSQL | **16-alpine** |
| 캐시·세션 | Redis | **7-alpine** |
| 프론트 런타임 | Node.js | **20 이상** |
| 프론트 번들러 | Vite | **8.x** |
| 프론트 | React | **19.x** |
| 컨테이너 | Docker Compose | v2 |

호스트에 JDK·Gradle 을 설치할 필요는 없다. 백엔드 빌드는 컨테이너 안에서 이뤄진다.
