# 1. 빌드 및 실행 매뉴얼

소스를 클론한 뒤 **로컬에서 Docker Compose 로 실행**하는 전 과정.

> EC2 + nginx(HTTPS) 운영 배포 절차는 [`docs/deploy.md`](../docs/deploy.md) 와
> [`docs/deploy-checklist.md`](../docs/deploy-checklist.md) 에 따로 있다.

## 1-2. 환경 변수

### 백엔드 (런타임) — `backend/.env`

`backend/.env.example` 을 복사해 만든다. **DB·CORS·JWT·카카오 5개는 비어 있으면
컨테이너가 뜨지 않는다.** 외부 API 키는 비어 있어도 기동되고, 해당 기능을 실제로
호출할 때 502 가 난다.

| 변수 | 필수 | 로컬 값 예시 / 설명 |
|---|---|---|
| `POSTGRES_DB` | ✅ | `ieumgil` |
| `POSTGRES_USER` | ✅ | `ieumgil` |
| `POSTGRES_PASSWORD` | ✅ | 임의. **`#` 을 쓰지 말 것** — .env 에서 주석으로 잘린다 |
| `JWT_SECRET` | ✅ | **32자 이상**. `openssl rand -base64 36` |
| `KAKAO_CLIENT_ID` | ✅ | 카카오 REST API 키 |
| `KAKAO_CLIENT_SECRET` | — | 카카오 콘솔에서 Client Secret 을 켰다면 필수 |
| `KAKAO_REDIRECT_URI` | ✅ | `http://localhost:5173/oauth/kakao/callback` |
| `CORS_ALLOWED_ORIGINS` | ✅ | `http://localhost:5173` |
| `AUTH_REFRESH_COOKIE_SECURE` | — | 로컬(HTTP)은 `false` |
| `AUTH_REFRESH_COOKIE_SAME_SITE` | — | `Lax` |
| `DDL_AUTO` | — | 로컬은 `update` (엔티티 기준 테이블 자동 생성) |
| `BACKEND_PORT` | — | 호스트 노출 포트. 기본 `8080` |
| `KAKAO_REST_API_KEY` | — | 장소 검색·길찾기. 없으면 해당 기능 502 |
| `ODSAY_API_KEY` | — | 대중교통 경로. 없으면 교통 추천 502 |
| `TOUR_API_KEY` | — | 축제 정보. **"Decoding" 값**을 넣을 것 (Encoding 값은 이중 인코딩으로 401) |
| `GMS_API_KEY` | — | AI 챗봇. 없으면 챗봇 502 |
| `OPINET_API_KEY` | — | 유가. 없으면 상수 유가로 조용히 대체(에러 아님) |

### 프론트엔드 (**빌드 시점**) — `frontend/.env`

⚠️ Vite 는 `VITE_*` 값을 **번들 소스에 문자열로 치환해 넣는다.** 런타임 환경변수가
아니므로 값이 바뀌면 dev server 를 재시작하거나 다시 빌드해야 한다.

| 변수 | 로컬 값 | 설명 |
|---|---|---|
| `VITE_API_BASE_URL` | `/api` | 절대주소가 아닌 **상대경로**. dev server 프록시를 타므로 브라우저가 보기엔 같은 오리진이 되고, refreshToken 쿠키가 first-party 로 저장된다 |
| `VITE_KAKAO_REST_API_KEY` | 카카오 REST API 키 | 카카오 로그인 인가 URL 의 `client_id` |
| `VITE_KAKAO_REDIRECT_URI` | `http://localhost:5173/oauth/kakao/callback` | 카카오 콘솔 등록값과 **글자까지** 같아야 함 |
| `VITE_API_PROXY_TARGET` | 비움 (= `http://localhost:8080`) | `/api`·`/ws` 를 중계할 백엔드 주소. 백엔드를 원격에 띄웠다면 그 주소 |

`vite.config.js` 가 `/api` 와 `/ws` 를 이 대상으로 프록시한다. **`/ws` 에는
`ws: true` 가 걸려 있어** STOMP WebSocket 도 같은 오리진으로 흐른다 — 배포의
nginx 리버스 프록시 구성과 같은 모양이다.

## 1-3. 클론부터 실행까지

### 사전 준비

- Docker Desktop / Docker Engine (Compose v2 포함) 실행 중
- Node.js 20 이상
- 카카오 개발자 앱 1개 ([02 문서](./02-외부-서비스.md) 참고)

### ① 클론

```bash
git clone <저장소 URL> ieumgil
cd ieumgil
```

### ② 백엔드 환경 변수

```bash
cd backend
cp .env.example .env
# 편집기로 .env 를 열어 값 채우기 (1-2 표 참고)
```

### ③ 백엔드 스택 기동 — Docker Compose

`backend`, `postgres`, `redis` 세 컨테이너가 함께 뜬다.
**PostgreSQL·Redis 이미지도 이 저장소의 Dockerfile 로 함께 빌드**된다
(타임존·초기화 스크립트·redis.conf 포함).

```bash
docker compose up -d --build
```

첫 실행은 Gradle 의존성을 받느라 5~10분 걸릴 수 있다.

**확인**

```bash
docker compose ps                 # 세 컨테이너가 Up / Up (healthy)
docker compose logs -f backend    # "Started ...Application" 확인 후 Ctrl+C
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8080/api/projects
# → 401 이면 정상 기동 (인증 없이 호출했으므로)
```

접속 정보

| 대상 | 주소 |
|---|---|
| 백엔드 API | `http://localhost:8080/api` |
| Swagger UI | `http://localhost:8080/swagger-ui.html` |
| PostgreSQL | `localhost:5432` (127.0.0.1 바인딩) |
| Redis | `localhost:6379` (127.0.0.1 바인딩) |

### ④ 프론트엔드 환경 변수

```bash
cd ../frontend
cp .env.example .env      # 없으면 새로 작성 (1-2 표 참고)
```

### ⑤ 프론트엔드 실행

```bash
npm install
npm run dev
```

→ **`http://localhost:5173`** 에서 접속.

> 프론트엔드는 컨테이너에 올리지 않는다. Vite dev server 가 `/api`·`/ws` 를
> 백엔드로 프록시하므로 브라우저 입장에서 **단일 오리진**이 되고, 이 구조가
> 배포(nginx 리버스 프록시)와 같은 모양이다.

### ⑥ 종료

```bash
cd ../backend
docker compose stop        # 컨테이너만 정지 (데이터 유지)
docker compose down        # 컨테이너 제거 (볼륨은 유지되므로 데이터는 남는다)
docker volume rm ieumgil_postgres-data ieumgil_redis-data   # 데이터까지 삭제
```

## 1-4. 실행 시 특이사항 ★

### ① 스키마는 자동 생성된다 — 신규 설치에 마이그레이션은 불필요

로컬 기본값 `DDL_AUTO=update` 로 기동하면 엔티티 기준으로 테이블이 만들어진다.
`migration/*.sql` 은 **이미 운영 중인 DB 를 새 버전으로 이관할 때** 쓰는 것이라,
빈 DB 에서 시작하는 로컬 실행에는 필요 없다.

다만 인덱스는 Hibernate 가 만들어 주지 않으므로, 데이터가 많은 상태로 성능을 볼
거라면 `001`·`002` 만 추가로 돌린다. 자세한 내용은 [03 문서](./03-DB-덤프.md).

### ② `VITE_*` 는 런타임 값이 아니다

`frontend/.env` 를 고쳤으면 **dev server 를 재시작**해야 반영된다. 실행 중 변경은
번들에 들어가지 않는다.

### ③ 카카오 Redirect URI 는 글자까지 같아야 한다

`frontend/.env` 의 `VITE_KAKAO_REDIRECT_URI`, `backend/.env` 의
`KAKAO_REDIRECT_URI`, 카카오 콘솔의 등록값 **셋이 모두 동일**해야 한다.
끝 슬래시 하나만 달라도 `KOE006` 으로 로그인이 실패한다.

### ④ 카카오 지도는 도메인 등록이 필요하다

카카오 콘솔 > 앱 설정 > 플랫폼 > Web > 사이트 도메인에 `http://localhost:5173` 을
등록해야 지도가 렌더링된다. 등록하지 않으면 **로그인은 되는데 지도만 회색**으로
나오고, 콘솔에도 뚜렷한 에러가 남지 않아 원인을 찾기 어렵다.

### ⑤ 음성 채팅은 `localhost` 에서만 동작한다 (HTTP 기준)

`getUserMedia` 는 **보안 컨텍스트(HTTPS 또는 localhost)** 에서만 허용된다.

| 접속 주소 | 음성 |
|---|---|
| `http://localhost:5173` | ⭕ 동작 |
| `http://<내부IP>:5173` | ❌ 마이크 접근 불가 |
| `https://<도메인>` | ⭕ 동작 |

같은 이유로 초대 링크 복사(`navigator.clipboard`)도 IP 접속에서는 동작하지 않는다.
**다른 기기에서 접속해 시연하려면 HTTPS 가 필요하다.**

### ⑥ 실시간 협업 테스트는 계정 두 개가 필요하다

접속 배지·라이브 커서·편집 배지는 `memberId` 기준이라 **같은 계정의 두 탭은 서로를
"남"으로 보지 않는다.** 일반 창 + 시크릿 창에 서로 다른 카카오 계정으로 로그인한다.

### ⑦ 포트 충돌

| 포트 | 용도 | 충돌 시 |
|---|---|---|
| 8080 | 백엔드 | `.env` 의 `BACKEND_PORT` 변경 + `VITE_API_PROXY_TARGET` 을 맞춰 수정 |
| 5173 | Vite dev server | Vite 가 자동으로 5174 등으로 옮긴다. 이때 카카오 Redirect URI 도 함께 바꿔야 한다 |
| 5432 / 6379 | PostgreSQL / Redis | 호스트에 이미 떠 있으면 compose 의 ports 매핑을 수정 |

### ⑧ 포트는 `127.0.0.1` 에만 바인딩되어 있다

PostgreSQL·Redis 는 `127.0.0.1:5432`, `127.0.0.1:6379` 로 묶여 있다.
**`0.0.0.0` 으로 바꾸지 않는다** — 특히 Redis 는 비밀번호가 없어서 무인증 노출 시
원격 코드 실행까지 이어진다. 원격 조회가 필요하면 SSH 터널을 쓴다.

### ⑨ 메모리

`mem_limit` 이 걸려 있다(backend 1g / postgres 512m / redis 256m). 백엔드는
`-XX:MaxRAMPercentage=75` 라 제한이 없으면 **호스트 전체의 75%** 를 힙 상한으로
잡는다. 제한을 풀지 않는다.

### ⑩ 알려진 제약

| 항목 | 내용 |
|---|---|
| TURN 서버 없음 | 공개 STUN 만 사용. 서로 다른 NAT 뒤의 두 사용자 간 음성이 연결되지 않을 수 있다 |
| 오프라인 편집 큐잉 없음 | 네트워크 단절 중 편집은 큐에 쌓이지 않고, 재연결 시 서버 상태로 재동기화 |
| 모바일 | 읽기 전용 (편집 UI 비노출) |

## 1-5. 계정·프로퍼티 정의 파일 목록

민감 정보가 들어가는 파일. **`.env` 계열은 전부 `.gitignore` 로 제외되어 커밋되지
않으며, 템플릿(`.example`)만 저장소에 있다.**

| 파일 | 커밋 | 내용 |
|---|---|---|
| `backend/.env` | ❌ 제외 | DB 계정·비밀번호, `JWT_SECRET`, 카카오 OAuth, 외부 API 키 전부 |
| `backend/.env.example` | ✅ | 위 항목의 빈 템플릿 + 설명 |
| `frontend/.env` | ❌ 제외 | `VITE_KAKAO_REST_API_KEY`, `VITE_KAKAO_REDIRECT_URI`, `VITE_API_BASE_URL`, `VITE_API_PROXY_TARGET` |
| `backend/src/main/resources/application.yaml` | ✅ | **비밀값 없음.** 전부 `${ENV}` 참조. 타임아웃·토큰 유효기간 등 고정 설정만 |
| `backend/docker-compose.yml` | ✅ | 값은 `${ENV}` 참조 |
| `backend/docker/redis/redis.conf` | ✅ | Redis 설정. **비밀번호 미설정** — 외부 바인딩 금지 |
| `frontend/src/features/dashboard/map/addressLookup.js` | ✅ | **카카오 지도 JS 키가 상수로 하드코딩되어 있다** (아래 참고) |

### 하드코딩된 키에 대한 설명

`addressLookup.js` 의 카카오 **JS 키**는 지도 SDK 렌더링용이다. JS 키는 도메인
등록으로 사용처가 제한되며(카카오 콘솔 > 플랫폼 > Web > 사이트 도메인), 브라우저에
노출되는 것이 정상적인 사용 방식이다.

다만 현재 **로그인용 REST 키도 번들에 함께 들어간다**(`VITE_KAKAO_REST_API_KEY`).
SPA 에서 OAuth 인가 URL 을 만들려면 불가피하지만, 이 키는 REST 호출에도 쓸 수 있어
**할당량 도용 위험**이 있다. 개선 방향은 지도·장소용 앱을 분리해 JS 키만 프론트에
두는 것이다. 단 **OAuth 는 기존 앱을 유지해야 한다** — 카카오는 앱마다 `kakaoId` 가
달라, 앱을 옮기면 기존 회원이 전부 신규 가입자가 된다.

### 계정 정보

| 대상 | 계정 | 위치 |
|---|---|---|
| PostgreSQL | `POSTGRES_USER` / `POSTGRES_PASSWORD` | `backend/.env` |
| Redis | 인증 없음 | — (127.0.0.1 바인딩으로만 보호) |
| 서비스 로그인 | **카카오 소셜 로그인 전용.** 자체 회원가입·비밀번호 없음 | — |
| 관리자 계정 | 없음 (관리자 기능 미구현) | — |
