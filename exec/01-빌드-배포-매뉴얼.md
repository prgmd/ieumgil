# 1. 빌드 및 실행 매뉴얼

저장소를 클론해 **로컬에서 빌드하고 실행**하는 전 과정.

```
STEP 1  저장소 클론
STEP 2  backend/.env 작성
STEP 3  docker compose up -d --build backend      ← backend + postgres + redis
STEP 4  frontend/.env 작성
STEP 5  npm install
STEP 6  npm run dev
```

→ **`http://localhost:5173`** 접속

프론트엔드는 컨테이너에 올리지 않는다. Vite dev server 가 `/api`·`/ws` 를 백엔드로
프록시하므로 브라우저 입장에서 **단일 오리진**이 되고, 이 구조가 배포(nginx 리버스
프록시)와 같은 모양이다.

```
브라우저 ──> Vite dev server (5173)
               ├─ 정적 자원
               ├─ /api  ─┐
               └─ /ws   ─┤ 프록시 (ws: true)
                         ↓
               ┌─ Docker Compose ─────────────────────┐
               │  backend (8080) ── postgres (5432)   │
               │                 └─ redis (6379)      │
               └──────────────────────────────────────┘
```

```bash
# 카카오 로그인 설정
# 카카오 개발자센터(https://developers.kakao.com) > 내 애플리케이션 > 앱 키 > REST API 키

VITE_KAKAO_REDIRECT_URI=http://localhost:5173/oauth/kakao/callback

# API 서버 기본 주소 (버전 prefix 포함)
# 절대주소가 아니라 상대경로를 쓴다 → vite dev server의 /api 프록시를 타게 되고,

# /api 요청을 실제로 중계할 백엔드 주소 (vite.config.js의 server.proxy.target)
# - 비워두면 http://localhost:8080 (백엔드도 로컬 docker compose로 띄운 경우)
# - 백엔드를 개발서버에 띄웠다면 아래 주석을 풀고 IP를 채울 것 (8080은 Jenkins가 점유)

```

| 변수 | 값 | 비고 |
|---|---|---|
| `VITE_KAKAO_REST_API_KEY` | 카카오 REST API 키 | 백엔드 `KAKAO_CLIENT_ID` 와 동일 |
| `VITE_KAKAO_REDIRECT_URI` | `http://localhost:5173/oauth/kakao/callback` | 카카오 콘솔·백엔드와 세 곳이 일치해야 함 |
| `VITE_API_BASE_URL` | `/api` | 상대경로 고정 |
| `VITE_API_PROXY_TARGET` | `http://localhost:8080` | 백엔드 호스트 포트 |


### ⚠️ `VITE_*` 는 빌드 시점 값이다

Vite 는 `VITE_*` 를 **번들 소스에 문자열로 치환해 넣는다.** 런타임 환경변수가
아니므로 `.env` 를 고쳤으면 **dev server 를 재시작**해야 반영된다.

## 1-3. 실행 시 특이사항 ★

### ① 스키마는 자동 생성된다 — 신규 설치에 마이그레이션은 불필요

`DDL_AUTO=update` 로 기동하면 엔티티 기준으로 테이블이 만들어진다.
`backend/docker/postgres/migration/*.sql` 은 **이미 운영 중인 DB 를 새 버전으로
이관할 때** 쓰는 것이라, 빈 DB 로 시작하는 로컬 실행에는 필요 없다.

인덱스는 Hibernate 가 만들지 않으므로, 데이터를 많이 넣고 성능을 볼 때만
`001`·`002` 를 추가로 돌린다. → [03 문서](./03-DB-덤프.md)

### ② 카카오 Redirect URI 는 세 곳이 글자까지 같아야 한다

| 위치 | 값 |
|---|---|
| 카카오 콘솔 | `http://localhost:5173/oauth/kakao/callback` |
| `backend/.env` 의 `KAKAO_REDIRECT_URI` | 동일 |
| `frontend/.env` 의 `VITE_KAKAO_REDIRECT_URI` | 동일 |

끝 슬래시 하나만 달라도 `KOE006` 으로 로그인이 실패한다.

### ③ 카카오 지도는 도메인 등록이 필요하다

카카오 콘솔 > 앱 설정 > 플랫폼 > Web > 사이트 도메인에 `http://localhost:5173` 을
등록해야 지도가 렌더링된다. 없으면 **로그인은 되는데 지도만 회색**으로 나오고,
콘솔에도 뚜렷한 에러가 남지 않아 원인을 찾기 어렵다.

### ④ 음성 채팅은 `localhost` 로 접속해야 동작한다

`getUserMedia` 는 **보안 컨텍스트(HTTPS 또는 localhost)** 에서만 허용된다.

| 접속 주소 | 음성 |
|---|---|
| `http://localhost:5173` | ⭕ 동작 |
| `http://<내부IP>:5173` | ❌ 마이크 접근 불가 |
| `https://<도메인>` | ⭕ 동작 |

같은 이유로 초대 링크 복사(`navigator.clipboard`)도 IP 접속에서는 동작하지 않는다.
**다른 기기에서 접속해 시연하려면 HTTPS 가 필요하다.**

### ⑤ 실시간 협업 테스트에는 계정 두 개가 필요하다

접속 배지·라이브 커서·편집 배지는 `memberId` 기준이라 **같은 계정의 두 탭은 서로를
"남"으로 보지 않는다.** 일반 창 + 시크릿 창에 **서로 다른 카카오 계정**으로
로그인해야 실시간 동작을 확인할 수 있다.

### ⑥ 포트 충돌

| 포트 | 용도 | 충돌 시 |
|---|---|---|
| 8080 | 백엔드 | `backend/.env` 의 `BACKEND_PORT` 변경 + `VITE_API_PROXY_TARGET` 을 같이 수정 |
| 5173 | Vite dev server | Vite 가 자동으로 5174 등으로 옮긴다. **이때 카카오 Redirect URI 세 곳도 함께 바꿔야 한다** |
| 5432 / 6379 | PostgreSQL / Redis | 호스트에 이미 떠 있으면 `backend/docker-compose.yml` 의 ports 매핑 수정 |

### ⑦ 포트는 `127.0.0.1` 에만 바인딩되어 있다

PostgreSQL·Redis 는 `127.0.0.1:5432`, `127.0.0.1:6379` 로 묶여 있다.
**`0.0.0.0` 으로 바꾸지 않는다** — 특히 Redis 는 비밀번호가 없어서 무인증 노출 시
원격 코드 실행까지 이어진다. 원격 조회가 필요하면 SSH 터널을 쓴다.

### ⑧ 메모리

`mem_limit` 이 걸려 있다(backend 1g / postgres 512m / redis 256m). 백엔드는
`-XX:MaxRAMPercentage=75` 라 제한이 없으면 **호스트 전체의 75%** 를 힙 상한으로
잡는다. 제한을 풀지 않는다.

### ⑨ 알려진 제약

| 항목 | 내용 |
|---|---|
| TURN 서버 없음 | 공개 STUN 만 사용. 서로 다른 NAT 뒤의 두 사용자 간 음성이 연결되지 않을 수 있다 |
| 오프라인 편집 큐잉 없음 | 네트워크 단절 중 편집은 큐에 쌓이지 않고, 재연결 시 서버 상태로 재동기화 |
| 모바일 | 읽기 전용 (편집 UI 비노출) |

## 1-4. 계정·프로퍼티 정의 파일 목록

민감 정보가 들어가는 파일. **`.env` 두 개는 `.gitignore` 로 제외되어 커밋되지
않는다.** 저장소에는 값이 남지 않으므로, **이 문서(STEP 2·4)의 템플릿이 유일한
기준**이다.

| 파일 | 커밋 | 내용 |
|---|---|---|
| `backend/.env` | ❌ 제외 | DB 계정·비밀번호, `JWT_SECRET`, 카카오 OAuth, 외부 API 키 전부 → **STEP 2** |
| `frontend/.env` | ❌ 제외 | `VITE_KAKAO_REST_API_KEY`, `VITE_KAKAO_REDIRECT_URI`, `VITE_API_BASE_URL`, `VITE_API_PROXY_TARGET` → **STEP 4** |
| `backend/src/main/resources/application.yaml` | ✅ | **비밀값 없음.** 전부 `${ENV}` 참조. 타임아웃·토큰 유효기간 등 고정 설정만 |
| `backend/docker-compose.yml` | ✅ | 값은 `${ENV}` 참조 |
| `backend/docker/redis/redis.conf` | ✅ | Redis 설정. **비밀번호 미설정** — 외부 바인딩 금지 |
| `frontend/src/features/dashboard/map/addressLookup.js` | ✅ | **카카오 지도 JS 키가 상수로 하드코딩되어 있다** (아래) |

### 하드코딩된 키에 대한 설명

`addressLookup.js` 의 카카오 **JS 키**는 지도 SDK 렌더링용이다. JS 키는 도메인
등록으로 사용처가 제한되며(카카오 콘솔 > 플랫폼 > Web > 사이트 도메인), 브라우저에
노출되는 것이 정상적인 사용 방식이다.

다만 현재 **로그인용 REST 키도 번들에 함께 들어간다**(`VITE_KAKAO_REST_API_KEY`).
SPA 에서 OAuth 인가 URL 을 만들려면 불가피하지만, 이 키는 REST 호출에도 쓸 수 있어
**할당량 도용 위험**이 있다. 개선 방향은 지도·장소용 앱을 분리해 JS 키만 프론트에
두는 것이다. 단 **OAuth 는 기존 앱을 유지해야 한다** — 카카오는 앱마다 `kakaoId` 가
달라, 앱을 옮기면 기존 회원이 전부 신규 가입자가 된다.

### 계정 정보

| 대상 | 계정 | 위치 |
|---|---|---|
| PostgreSQL | `POSTGRES_USER` / `POSTGRES_PASSWORD` | `backend/.env` |
| Redis | 인증 없음 | — (127.0.0.1 바인딩으로만 보호) |
| 서비스 로그인 | **카카오 소셜 로그인 전용.** 자체 회원가입·비밀번호 없음 | — |
| 관리자 계정 | 없음 (관리자 기능 미구현) | — |

## 1-5. 문제 해결

| 증상 | 먼저 볼 곳 |
|---|---|
| **요청은 나가는데 백엔드 로그가 안 찍힘** | `VITE_API_PROXY_TARGET` 오타·포트 불일치. `npm run dev` 터미널의 proxy error 확인 |
| 컨테이너가 안 뜸 | `JWT_SECRET` 32자 미만, 필수 5개 누락 |
| 로그인 실패 (KOE006) | Redirect URI 세 곳이 글자까지 같은지 |
| 지도만 회색 | 카카오 콘솔 > 플랫폼 > Web > 사이트 도메인 |
| 마이크가 안 잡힘 | `localhost` 로 접속했는지 (IP 접속은 불가) |
| 실시간이 상대 화면에 안 보임 | **다른 계정**으로 로그인했는지 (같은 계정 두 탭은 서로를 남으로 안 봄) |
| `.env` 를 고쳤는데 반영이 안 됨 | 프론트는 dev server 재시작, 백엔드는 `docker compose up -d` |
| 챗봇·교통·축제가 502 | 해당 외부 API 키 미설정 ([02 문서](./02-외부-서비스.md)) |

## 부록. EC2 배포 (요약)

운영 배포는 **이미지를 로컬에서 굽고 EC2 가 pull** 하는 방식이다. EC2 에는 소스를
클론하지 않고 `docker-compose.yml` 과 `.env` 두 파일만 둔다.

```
브라우저 ──HTTPS(443)──> nginx (EC2 호스트, Let's Encrypt)
                            ├─ /      → 127.0.0.1:5173   frontend
                            ├─ /api/  → 127.0.0.1:8081   backend
                            └─ /ws    → 127.0.0.1:8081   backend (WebSocket)
```

```bash
# 로컬 PC — 이미지 빌드 후 레지스트리에 push
cd frontend
VITE_KAKAO_REDIRECT_URI=https://<도메인>/oauth/kakao/callback \
  FRONTEND_IMAGE_REPO=<계정>/ieumgil-frontend IMAGE_TAG=<태그> docker compose build
docker push <계정>/ieumgil-frontend:<태그>

cd ../backend
docker build --platform linux/amd64 -t <계정>/ieumgil-docker:<태그> .
docker push <계정>/ieumgil-docker:<태그>
```

```bash
# EC2 — 태그만 바꿔 받아 켠다
cd ~/ieumgil
vi .env                          # BACKEND_TAG / FRONTEND_TAG
docker compose pull && docker compose up -d
```

### 로컬과 다른 점 세 가지

| 항목 | 로컬 | 배포 |
|---|---|---|
| 프론트엔드 | Vite dev server | **컨테이너(nginx + 정적 번들)** |
| `/api`·`/ws` 프록시 | Vite dev server | **호스트 nginx** |
| HTTPS | 불필요 (localhost 는 보안 컨텍스트) | **필수** — 음성·클립보드가 HTTPS 를 요구 |

### 배포에서 특히 주의할 것

- **nginx `/ws` 에 Upgrade 헤더 3줄이 없으면** 실시간 기능 전체가 에러 없이 죽는다
- **`VITE_*` 는 이미지에 구워진다** — 도메인을 바꾸려면 이미지를 다시 굽는다
- **`DDL_AUTO=update` 여도 데이터 마이그레이션은 수동**이다 (특히 006)
- compose 의 `name:` 이 기존과 다르면 **빈 DB 가 새로 생긴다**

전체 절차·nginx 설정 전문·검증 체크리스트는
[`docs/deploy.md`](../docs/deploy.md) 와 [`docs/deploy-checklist.md`](../docs/deploy-checklist.md) 에 있다.
