# 3. DB 덤프 및 스키마

DBMS: **PostgreSQL 16** (Docker, `TZ=Asia/Seoul`)

| 파일 | 내용 |
|---|---|
| `exec/db/ieumgil-dump.sql` | 최신 덤프 (스키마 + 데이터) |
| `exec/db/ieumgil-schema.sql` | 스키마만 (데이터 제외) |

---

> **빈 DB 에서 새로 시작하는 경우 이 문서는 필요 없다.** `DDL_AUTO=update` 로
> 백엔드를 띄우면 엔티티 기준으로 테이블이 자동 생성된다. 아래 내용은
> **기존 데이터를 옮기거나 운영 DB 를 이관할 때** 쓴다.

---

## 덤프 생성

컨테이너 이름은 로컬·배포 서버가 같다(`ieumgil-postgres`).

```bash
# 스키마 + 데이터
docker exec -i ieumgil-postgres sh -c \
  'pg_dump -U $POSTGRES_USER -d $POSTGRES_DB --no-owner --no-privileges' \
  > ieumgil-dump.sql

# 스키마만
docker exec -i ieumgil-postgres sh -c \
  'pg_dump -U $POSTGRES_USER -d $POSTGRES_DB --schema-only --no-owner --no-privileges' \
  > ieumgil-schema.sql
```

`--no-owner --no-privileges` 를 주는 이유는 복원 대상의 DB 계정 이름이 달라도
그대로 들어가게 하기 위함이다.

로컬로 가져오기:

```bash
scp -i <키.pem> ubuntu@<도메인>:~/ieumgil-dump.sql exec/db/
```

## 복원

```bash
# 컨테이너가 떠 있는 상태에서
docker exec -i ieumgil-postgres sh -c \
  'psql -U $POSTGRES_USER -d $POSTGRES_DB' < exec/db/ieumgil-dump.sql
```

빈 DB 에 처음 붓는 경우가 아니라면 기존 데이터와 충돌한다. 완전히 새로 만들려면
볼륨을 지우고 컨테이너를 다시 띄운 뒤 복원한다.

```bash
docker compose down                       # 스택 정지
docker volume rm ieumgil_postgres-data    # ⚠️ 기존 데이터가 사라진다
docker compose up -d postgres             # 빈 DB 로 재생성 (initdb 실행)
# 헬스체크가 healthy 가 된 뒤 복원
```

## 스키마 구성 순서 (덤프 없이 처음부터 만들 때)

### ① 초기화 스크립트 — 자동

`backend/docker/postgres/initdb/01-extensions.sql` 이 **데이터 디렉터리가 비어 있을
때 1회만** 자동 실행된다(PostgreSQL 이미지의 `docker-entrypoint-initdb.d` 규약).
확장(extension) 설치가 들어 있다.

### ② 테이블 생성 — Hibernate

`DDL_AUTO=update` 로 백엔드를 기동하면 엔티티 기준으로 테이블이 생성된다.
`none` 이면 생성되지 않으므로 덤프 복원이 필요하다.

**신규 설치는 여기까지로 끝난다.** 엔티티가 이미 최신 스키마(`start_offset_minutes`
등)를 담고 있으므로, 아래 ③의 마이그레이션은 **이미 운영 중인 옛 DB 를 새 버전으로
이관할 때만** 필요하다. 인덱스는 Hibernate 가 만들지 않으므로 데이터가 많은 상태로
성능을 볼 때만 `001`·`002` 를 추가로 돌린다.

### ③ 마이그레이션 — 기존 DB 이관 시에만 ★

`backend/docker/postgres/migration/` 의 스크립트를 **번호 순서대로** 실행한다.

| 번호 | 파일 | 내용 | 자동 반영 |
|---|---|---|---|
| 001 | `001-indexes.sql` | 기본 인덱스 | ❌ |
| 002 | `002-dashboard-indexes.sql` | 대시보드 조회 인덱스 | ❌ |
| 003 | `003-festival-homepage.sql` | 축제 홈페이지 컬럼 | 컬럼만 ⭕ |
| 004 | `004-transport-prefs.sql` | 교통 선호 설정 | 컬럼만 ⭕ |
| 005 | `005-block-last-edited-by.sql` | 마지막 편집자 컬럼 + **백필** | 컬럼만 ⭕ |
| 006 | `006-block-time-model.sql` | **블록 시간 모델 이관** | ❌ **필수 수동** |
| 007 | `007-drop-legacy-block-time.sql` | 옛 컬럼 제거 | ❌ **비가역** |

> **"자동 반영" 열의 의미** — `DDL_AUTO=update` 는 `ALTER TABLE ADD COLUMN` 만 한다.
> **데이터를 옮기거나 채우지 않고, 인덱스·제약도 만들지 않는다.**

### 실행 방법

```bash
docker exec -i ieumgil-postgres sh -c 'psql -U $POSTGRES_USER -d $POSTGRES_DB' \
  < backend/docker/postgres/migration/006-block-time-model.sql
```

## ⚠️ 006 — 가장 중요한 마이그레이션

블록의 시간 표현을 `day_no + start_time` 조합에서 **`start_offset_minutes` 단일
컬럼**(Day 1 00:00 기준 경과 분)으로 바꾼다.

**이걸 빠뜨리면** 기존 블록의 `start_offset_minutes` 가 전부 `NULL` 이 되고,
프론트엔드는 `NULL` 을 **후보(POOL)** 로 해석한다 —
**모든 일정이 타임라인에서 사라져 후보 목록으로 내려간다.**
데이터가 지워지는 것은 아니지만 사용자 눈에는 초기화된 것으로 보인다.

### 실행 후 검증 — 두 수가 같아야 한다

```bash
docker exec -i ieumgil-postgres sh -c 'psql -U $POSTGRES_USER -d $POSTGRES_DB -c \
  "SELECT count(*) FILTER (WHERE day_no IS NOT NULL)               AS on_day, \
          count(*) FILTER (WHERE start_offset_minutes IS NOT NULL) AS migrated \
     FROM block"'
```

표본 대조:

```sql
SELECT id, day_no, start_time, start_offset_minutes
  FROM block WHERE day_no IS NOT NULL ORDER BY id LIMIT 10;
-- start_offset_minutes == (day_no - 1) * 1440 + 시각(분) 이어야 한다
```

---

## ⚠️ 007 — 비가역

옛 컬럼(`day_no`, `start_time`, `end_time`)을 **DROP** 한다. 006 의 결과를 검증한
뒤에만 실행하고, **실행 후에는 구버전 백엔드로 롤백할 수 없다.**

시연·발표가 끝난 뒤에 정리 목적으로 실행하는 것을 권한다.
